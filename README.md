## Development Principles

### 1. 직접 이해하고 구현한다
저장소에 포함되는 코드는 작성 이유와 동작 과정을 이해하고 설명할 수 있어야 합니다. 실행 결과뿐 아니라 입력, 연산, 조건 분기, 반복 등 코드가 흘러가는 과정을 스스로 확인합니다.

### 2. 학습한 C 개념을 단계적으로 적용한다
현재 학습한 문법과 개념을 바탕으로 작은 예제부터 구현합니다. 새로운 개념이나 도구가 필요하면 먼저 학습하고 동작을 확인한 뒤 적용하며, 이해하지 못한 코드를 그대로 가져오지 않습니다.

### 3. AI 챗봇은 학습 보조로만 활용한다
AI 챗봇은 C 개념 설명, 오류 메시지 해석, 구현 방향에 대한 조언, 직접 작성한 코드의 리뷰와 디버깅 질문에 활용할 수 있습니다. 제안된 내용은 수업 자료나 신뢰할 수 있는 자료, 직접 컴파일·실행한 결과와 대조하고 스스로 설명할 수 있어야 합니다.

### 4. 바이브코딩과 AI 에이전트 개발을 사용하지 않는다
요구사항만 전달해 프로그램이나 과제 전체를 생성하는 바이브코딩과, AI가 저장소 파일을 직접 수정하거나 여러 단계의 구현을 대신하는 에이전트 방식은 사용하지 않습니다. 코드는 학습자가 직접 작성하며, 예제 코드를 참고할 때도 동작을 이해한 뒤 필요한 부분만 반영합니다.

### 5. 학습 기록의 맥락을 보존한다
수업 실습과 자기주도학습 결과를 구분하고, 학습 목적과 작성 과정을 드러내는 파일명과 주석을 유지합니다. 결과를 꾸미기 위해 학습 이력이나 코드 출처를 왜곡하지 않습니다.

### 6. 서로의 학습과 필요를 배려한다
친구가 학습이나 개발 환경에서 어려움을 겪으면 가능한 범위에서 먼저 살펴보고 기꺼이 돕습니다. 코드를 확인하는 사람의 상황과 필요도 고려해, 필요하면 글자를 키우고 가독성을 높여 내용을 편하게 확인할 수 있도록 합니다.

## 주석 작성 메모

소스 코드의 주석은 코드 옆에 덧붙이는 짧은 설명처럼 씁니다. 코드를 그대로 한국어로 옮겨 적기보다, 왜 이 코드가 필요한지나 처음 읽는 사람이 놓치기 쉬운 의도를 보충합니다. 예를 들어 함수의 역할, 매개변수의 의미, 입력을 처리하는 이유처럼 코드만으로 바로 드러나지 않는 정보를 간결하게 덧붙입니다. 코드가 바뀌면 주석도 함께 확인해 실제 동작과 어긋나지 않도록 합니다.
